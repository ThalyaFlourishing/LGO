Hybrid Approach: User Experience & Technical Workflow
User Story (What the user sees/does)
User exports gear data and runs the optimizer for the first time

The tool generates a new .toml file (e.g., gear-2024-04-22T1340.toml).
The file is clean—no user overrides or metadata yet.
User hand-edits fields in the .toml file

Example: Fills in Legendary Item stats, corrects a mis-detected value, etc.
User does NOT need to mark or flag edits in any way.
On subsequent exports (when running the optimizer again):

The tool detects that the same items/fields exist in both the previous and new files.
For each changed field, if it was manually edited previously (determined via automated tracking), the CLI prompts:
Code
The value for [SomeRing.Will] changed: old value (200) vs new export (100).
Overwrite your custom value with exporter’s value? (y/n)
Options at the start:
a = accept all, n = accept none, or proceed one-by-one.
(For Legendary items, no prompt is given—they’re always preserved.)
User makes selections

The choices are recorded and used for the new .toml file.
At the very end, the user can see a summary of what was preserved/overwritten.
Technical Details
A. How to Track Hand-Edits Automatically
In the .toml, add a special metadata section at the bottom or in a hidden file (e.g., .gear-overrides) that looks like:

TOML
# --- DO NOT EDIT BELOW ---
[__user_edits__]
"SomeRing.Will" = true
"SecondAgeSword.Finesse" = true
After every CLI reconciliation, update this metadata to reflect what the user modified and preserved in the last run.

On each merge, compare:

If a field was previously user-edited (marked in metadata): prompt before overwrite.
If a field was not edited by user (not in metadata): overwrite automatically with exporter value.
How to detect new hand-edits:
When reading the new .toml, compare user-edit markers in metadata section with actual .toml content.
If a value in the file differs from the exporter’s value, and wasn’t produced by the last export, consider it a hand-edit and add/keep its key in the metadata section for the next run.
B. Guided Interactive Reconciliation
Upon a new export, before committing final changes to the .toml file:

For each field with a non-matching value and a user-edit marker, display a prompt as shown above.
Honor user's batch choices as well as field-by-field decisions.
For Legendary items/stat fields (never exportable): always preserve those fields—no prompt needed.
After finalizing .toml, update the [__user_edits__] metadata to reflect:

Fields retained as user-edits (those not overwritten)
Fields reset to exporter values (remove their key from metadata)
C. Extra Features (Optional)
Let advanced users review or clear the [__user_edits__] section if they want a hard “reset.”
Create a CLI flag like --forget-edits to clear all user-edit markers in one go (for power users wanting a clean start).
Example (in practice)
Suppose the .toml initially is:

TOML
[item.SomeRing]
Will = 100
Might = 120

# --- DO NOT EDIT BELOW ---
[__user_edits__]
User hand-edits:

TOML
[item.SomeRing]
Will = 200
Might = 120

# --- DO NOT EDIT BELOW ---
[__user_edits__]
"SomeRing.Will" = true
On next export, new auto-export produces:

TOML
[item.SomeRing]
Will = 110
Might = 130

# --- DO NOT EDIT BELOW ---
[__user_edits__]
"SomeRing.Will" = true
CLI prompts:

Code
The value for [SomeRing.Will] changed: yours (200) vs exporter (110). Overwrite? (y/n)
The value for [SomeRing.Might] was not manually edited. Overwriting with exporter value (130).
User chooses n for Will, accepts Might overwrite.

Final file:

TOML
[item.SomeRing]
Will = 200
Might = 130

# --- DO NOT EDIT BELOW ---
[__user_edits__]
"SomeRing.Will" = true
Benefits
Invisible, friendly workflow: End users just edit fields; the tool silently tracks their hand-edits.
No “marker” clutter in main item data.
Easy recovery: Hard “reset” via batch accept or clearing metadata, without manual delete.
Power user and novice-friendly: CLI prompts can be quick-skipped but allow precision.
Legendary/support: Whole categories (like LI stats) can be globally marked as “always preserve.”
