# PR 1 — Refuse-on-Overflow Guard (coding-agent prompt)

**Repo:** ThalyaFlourishing/LGO  **Branch:** cut a feature branch from `main`.
**Model guidance:** `optimizer.rs` control-flow is frontier-model territory
(`docs/MODEL_GUIDANCE.md`). This PR changes `optimize`'s control flow and return
type — treat it accordingly.

## Context
`MAX_CANDIDATES_PER_SLOT = 8` is being redefined from an internal **truncation**
heuristic into a **supported-input contract**: if any single slot OR any paired
family (Wrist / Finger / Ear) has more than 8 owned candidates, the optimizer
must **refuse** (clear, actionable error) rather than silently truncating.
See `docs/Optimizer_Overhaul/07 - Locked Semantics and Rewrite Plan.md` §3.

This is PR 1 of 2. It does **only** the guard. It must **not** change the search
algorithm or the objective (that is PR 2). Keep this PR small and low-risk.

**Architecture note:** the optimizer runs on `lgo_<char>_gearReady.toml`, the
output of `resolve-slots`, where every item already has a canonical slot. Slot
assignment is owned entirely by `slot_resolver` / the items DB — NOT by the Lua
plugin, which exports item names + character + class only and has no slot data.

## Required changes

### 1. `src/optimizer.rs` — replace truncate-and-warn with refuse
- **Delete** the truncation block (currently ~lines 151–162: the
  `pool.len() > MAX_CANDIDATES_PER_SLOT` → warning + `pool.truncate(...)`).
- Add an error type:
  ```rust
  #[derive(Debug, Clone, PartialEq, Eq)]
  pub enum OptimizeError {
      TooManyCandidates { slot_label: String, count: usize, max: usize },
  }
  ```
  Implement `std::fmt::Display` and `std::error::Error` with an actionable
  message, e.g.:
  `Too many candidates for slot "Finger": 11 provided, maximum allowed is 8. Remove items from the 'lgo' chest and re-export before running 'lgo optimize'.`
- Change the entry point signature to:
  `pub fn optimize(...) -> Result<OptimizeResult, OptimizeError>`
- **Validation timing & scope:** after grouping items into per-canonical-slot
  pools (i.e. after `canonical_slot` folding, so Wrist1/Wrist2 count as ONE
  "Wrist" family — likewise Finger, Ear), and **before** building pairs / any
  search:
  - For each single slot, if `pool.len() > MAX_CANDIDATES_PER_SLOT` → return
    `Err(TooManyCandidates{...})` using the human slot label (reuse
    `slot_display`).
  - For each paired **family** (Wrist, Finger, Ear), validate the **family pool
    size** (the pre-pair count of owned items in that family), NOT the number of
    generated pairs. If it exceeds the cap → `Err(...)`.
  - Report the FIRST offending slot/family in a deterministic order (iterate
    `Slot::ALL`, mapping through `canonical_slot`, so the message is stable).
- The `warnings` field remains for other warnings (e.g. empty-slot
  placeholders); only the truncation warning is removed.

### 2. `src/main.rs` — handle the new Result
- `run_optimize` currently does `let result = optimizer::optimize(...);`
  (~line 144). Change to match on the `Result`:
  - `Ok(result)` → proceed to `report::print_report` as today.
  - `Err(OptimizeError::TooManyCandidates{ .. })` → `eprintln!` the actionable
    message and `process::exit(1)`, including the "remove items from the 'lgo'
    chest and re-export" guidance.

### 3. `src/lgo.lua` — total-candidate-count sanity warning (SOLE edit)
The plugin exports item names + character + class only; it has NO slot data and
must NOT attempt any per-slot or per-family counting. The ONLY change:
- Add a named constant near the top of the file:
  `local MAX_CANDIDATES_PER_SLOT = 8;  -- keep in sync with Rust optimizer`
- After building the combined export list in `ExportCombined`, print a single
  **non-blocking** NOTE based on the total instance count (`#out.names`), e.g.:
  `Print("NOTE: exported " .. #out.names .. " item names. The optimizer allows at most " .. MAX_CANDIDATES_PER_SLOT .. " candidates per slot/family; if one slot exceeds that, 'lgo optimize' will refuse until you remove some. (Rust performs the authoritative per-slot check after resolve-slots.)")`
- Do **not** block the export. Do **not** compute slots. The Rust guard is
  authoritative.
