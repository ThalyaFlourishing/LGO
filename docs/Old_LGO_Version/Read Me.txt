﻿LotRO Gear Optimizer

This is a crude utility to find the optimal combinations of gear for a given stat. It is useful if you keep multiple items for a given slot and switch them out depending on the role you are playing. (e.g. swapping from your crit gear to your tactical mit gear when you switch from red to yellow) One could also compare gear you *don't* have yet, I suppose.

To use:

1. Enter the stats for your gear in the 'Gear.js' file. Keep it and the 'LGO.js' file in the same folder.
2. In a browser, open the 'LGO.HTML' file. You can do that by doing one of the following:
  a) Go to your browser and hit CTRL+O, navigate to the folder in which you put the files, select 'LGO.HTML' and hit the 'Open' button.
  b) Navigate to the folder in which you put the files, select 'LGO.HTML' and hit enter, or just double-click it.
3. When the file loads, it will display a report of which gear combinations add up to the best stat totals.

That's it!

How to enter your gear info:

In the file named 'Gear.js', edit the data as follows:
  1. Replace the names with the actual names of your gear:
    - Open the file named 'Gear.js' in a text editor.
    - Take off all your gear and enter your three important base stats in the first block, labeled 'Base_Stats'. 
    - For each other slot, enter the stats of the items you have to choose from, as shown in the template. 
    - For slots for which you don't have multiple items to consider, add their items in anyway, but delete the other two lines. Adding them in will give you approximately the stat totals you will actually have, rather than only from the swappable gear. Not deleting the unused lines could make the program take too long to finish. (See below * )
    - If you have more than three choices for a given slot, just copy-paste another line in. Just keep in mind that every line you add increases the computation time. (If you have fewer than 12 swappable slots, it's not a big deal.)
    - IMPORTANT: If you have two of the same item for the ear, wrist, or finger slots, you must change the name of at least one of them to avoid duplication issues. e.g. if you have two Red-Eye Rings, change the name of at least one of them to 'RedEyeRing_02' or something. This is clunky and dumb, but again, I'm not really a programmer. Sorry.
    - You don't have to spell the names correctly. You can call the gear items whatever you want, as long as you know what you mean.
    - Be careful to not accidentally delete the quote marks.
    - Save the file with no BOM encoding. Sometimes BOM can cause trouble. If you're saving as UTF-8, you're good.
    - If you already have the LGO page up in your browser, you will need to refresh the page to see the changes. (CTRL+R)
  
  2. Replace the 'value' numbers with the actual stat numbers of your gear:
    - Don't use commas or periods. e.g. use this: value: 10000 , not this: value: 10,000 .
    - Be sure to add the bonus from an item's base stats. e.g. if an item has 1000 Agility, and that adds 2000 to your crit rating, add that in to the number you enter. It may be best to compare with the item in vs. the slot being empty to be sure you are gettng the correct value.
    - Don't forget off-stats! Agility, for example, contributes more to a Lore-Master's Crit Rating than Will does. So does Might!
    - Re: LI's: I strongly recommend just equipping/unequipping the LI's and noting the difference to get the values.
    - When you get a new piece of gear, simply edit the file to reflect the new name and stats.

(If you want to get ambitious and change their names in the output, just edit the 'LGO.js' file, lines 83 — 89, to replace each instance of 'crit' with 'outgoing_heal' or whatever you want, for example. They're just messages to the user; it doesn't affect the calculations.)

Only the total of a stat on an item matters. You must add duplicate stats on an item together before entering them, sorry.
IOW, do this:
      { name: "earring1", stats: [ { key: "crit", value: 10000 }, { key: "tact", value: 10 }, { key: "tmit", value: 10 } ] },
not this:
      { name: "earring1", stats: [ { key: "crit", value: 5000 }, { key: "tact", value: 10 }, { key: "tmit", value: 10 } ] },
      { name: "earring1", stats: [ { key: "crit", value: 5000 }, { key: "tact", value: 10 }, { key: "tmit", value: 10 } ] },

If you want to have swappable items in more than 10 slots, you can, but see the info at the bottom of this page before doing so!
Simply copy-paste one block of data in the 'Gear.js' file and fill in the names and stats with the new slot's info. One unit is from one left brace (' { ') in the left-most column to its corresponding right brace in the left-most column, (' } '), as shown in the example above. It can be copied from and pasted to anywhere in the list, just be sure you include the comma at the end of the block, and don't delete the last line: ' ]; '

If you want to compare fewer or more than three items in a given slot, just delete or copy-paste the line. There is no limit. You won't notice much of a performance difference by removing lines or blocks until you get past 12 blocks.

How to interpret the output:

The output is divided into two reports:
1. The best combinations.
2. ALL combinations.

The best section has four reports:
1. 'Max sum' : The combination of gear which gives the largest value of all the stats put together.
2. 'Max Critical Rating' : The combination of gear which gives the largest value of Critical Rating, or whichever stat you're actually tracking.
2. 'Max Tactical Mastery' : The combination of gear which gives the largest value of Critical Rating, or whichever stat you're actually tracking.
2. 'Max Tactical Mitigation' : The combination of gear which gives the largest value of Critical Rating, or whichever stat you're actually tracking.

The Combinatorial Explosion and computational demand:

Although there is technically no limit on how many gear slots you can compare, I recommend you don't try to compare more than 12 or 13. Why?

Unfortunatly, any kind of job like this has what is called O(n!)-complexity. This means that for each gear slot you use, it has to do everything you did before, again, once for each slot. Up until 11 slots, it's fine. Doesn't take more than a second or two.

But at 12 slots on my fairly-recent, reasonably-fast machine it takes 12 seconds. This means that adding one more will make it take 156 seconds, followed by:

14 slots:         2,148 seconds, which is 35 minutes and 48 seconds.

15 slots:        32,760 seconds, which is 9 hours and 6 minutes

16 slots:       524,160 seconds: just over 6 days

17 slots:     8,910,720 seconds: three-and-a-half months

18 slots:   160,392,960 seconds: 5.09 years

19 slots: 3,047,466,240 seconds: 96.63 years

So, yeah. No.

BUT! This is a JavaScript program, and JavaScript running in a browser is incredibly slow and inefficient. A proper version written in java or C++ would be incredibly much faster. Again, if you are that enterprising *real* computer programmer, please try it! Hell, port it to ForTran77 and see how high you can go on number of slots! (Just be sure to abstract your name strings to integers before running calculations)
