LGO COMMAND-LINE REFERENCE
==========================

LGO has three command surfaces: an in-game Lua plugin, a browser bookmarklet workflow on lotro-wiki.com, and the lgo Rust CLI. These run in different environments and are documented in separate sections below to avoid confusion.

SECTION 1 - IN-GAME PLUGIN COMMANDS
-----------------------------------
(typed in the LotRO chat window while the plugin is loaded)

  /lgo
    Show plugin help text (lists plugin subcommands and workflow reminder).

  /lgo export
    Export a unified gearlist from equipped items plus Shared Storage chest "LGO".
    Writes lgo_<character-name>_gearNames_<timestamp>.plugindata.
    Equipped craft tool (slot 19) and bridle (slot 21) are automatically excluded —
    there is no need to unequip them before exporting.

  /lgo export chest <name>
    Export equipped items (same exclusions as above) plus Shared Storage chest <name>.

SECTION 2 - BOOKMARKLET WORKFLOW!
--------------------------------
(no shell command form; browser-driven step that produces the stats .toml)

  1) Open https://lotro-wiki.com in your browser.
  2) Click the LGO Stats bookmarklet.
  3) Paste the contents of lgo_<character-name>_gearNames_<timestamp>.plugindata when prompted.
  4) Let the bookmarklet fetch item stats and generate TOML output.
     The generated TOML includes top-level character = "..." and class = "..." fields.
  5) Save the generated file as lgo_<character>_gearStats.toml into your character's AllServers directory.

SECTION 3 - LGO CLI (USER COMMANDS)
-----------------------------------

3.1 General notes
  - Verbs are case-insensitive (for example: optimize, Optimize, OPTIMIZE).
  - Switch names are also case-insensitive; switch values are not.
  - Verb aliases:
      build-db       | --build-db
      optimize       | --optimize       | -o
      resolve-slots  | --resolve-slots  | -r
      scrap-gear     | --scrap-gear     | -s
      base-stats     | --base-stats
  - Top-level reference switch:
      --statlist
  - Help/usage banner is printed by:
      lgo
      lgo --help
      lgo -h
      lgo help
  - When entering the file path/names of alternate data files, if the file name or any of the folders in the path have spaces, you'll need to put quote marks around it. Also, if you are using a bash window, remember to change the back slashes to forward slashes.

3.2 statlist
  lgo --statlist
    Print a two-column reference table of optimizer stat abbreviations and
    full stat names. Use these abbreviations in optimize goals.

    Example output:
      Stat Abbreviation  Stat Name
      -----------------  ------------------
          ml             Morale
          pw             Power
          am             Armour
          cr             CriticalRating
          fn             Finesse
          pm             PhysicalMastery
          tm             TacticalMastery
          oh             OutgoingHealing
          rs             Resistance
          cd             CriticalDefense
          ih             IncomingHealing
          bl             Block
          pa             Parry
          ev             Evade
          pt             PhysicalMitigation
          tt             TacticalMitigation

3.3 resolve-slots
  lgo resolve-slots
    Auto-detect lgo_<character>_gearStats.toml in the selected character's AllServers
    directory, resolve slot names via data/lgo_items.json, and merge the result into
    lgo_<character>_gearReady.toml.
    gearReady.toml is the canonical file for persistent manual corrections,
    including top-level [Virtues] plus each item's [item.EssenceTotals] block.
    resolve-slots keeps [InnateStats] followed immediately by [Virtues] near the
    top of the file. The bookmarklet-produced gearStats.toml should be treated
    as disposable input to resolve-slots.

    Filename matching for the character name is case-insensitive on Windows.

  lgo resolve-slots --character <name>
  lgo resolve-slots -c <name>
    Resolve slots using that character's AllServers directory.

  lgo resolve-slots --force
   In --force mode, the program will ask you, item by item, before changing or removing anything. Each prompt looks like:
      Overwrite stats for "Test Helm"? (y/n/a)
   or:
      Remove "Old Sword" (no longer in export)? (y/n/a)
   Type y to allow the change, n to keep your existing data, or a to allow that kind of change for all remaining items without further prompting (overwrites and removals are tracked separately, so an a to one kind does not automatically apply to the other).

3.4 optimize
  lgo optimize <stat:min> [<stat:min> ...]
    Run optimization with stat goals in priority order. The optimizer first prefers
    builds that meet higher-priority goals, then gets still-unmet goals as close to
    their minima as possible, and only then uses extra raw totals as a polish/tiebreak.
    A minimum of 0 means no floor, but maximize that stat only in the later polish stage.
    Auto-discovers lgo_<character>_gearReady.toml from the character's AllServers directory.
    By default optimize prints the report only to the terminal.

  lgo optimize --character <name> <stat:min> ...
  lgo optimize -c <name> <stat:min> ...
    Use the specified character's AllServers folder for auto-discovery.

  lgo optimize --file <path> <stat:min> ...
  lgo optimize -f <path> <stat:min> ...
    Optimize using the explicit canonical gear TOML you provide.
    The file is read directly; no plugindata input is needed. If the file name
    or any of the folders in the path have spaces, you'll need to put quote
    marks around it.
    Character and class are read from the TOML's top-level fields if present.
    Top-level [Virtues] values are matched case-insensitively, after trimming
    surrounding whitespace, against the top-level keys in data/lgo_virtues.json.
    Empty values are ignored. Unknown or duplicate non-empty Virtue names are
    hard errors.
    Per-item [item.EssenceTotals] values in gearReady.toml are merged into the
    effective item totals before optimization.

    optimize also derives the raw Base stats (Might, Agility, Vitality, Will,
    Fate) carried in gearReady.toml — innate, per-item, and essence values —
    plus any raw Base stats granted by selected Virtues — into tracked-stat
    contributions using the per-class coefficients in
    data/base_stat_derivations.json. Selected Virtue tracked stats contribute
    directly as fixed baseline totals. Both data files are resolved relative to
    the current directory (same convention as build-db), so run optimize from a
    directory containing the data/ folder. optimize errors clearly if the class
    entry, derivation file, or needed virtue data file is missing.
    The report content includes the chosen gear, goal summary, the full projected
    16 tracked stats (zero rows included), and the combined raw Base-stat pool.

    Combined example:
      lgo optimize --file path\to\lgo_Thalya_gearReady.toml tm:450000 cr:350000 fn:0


  lgo optimize --to-file <stat:min> ...
    Also write a plain-text report and a self-contained HTML report into an
    LGO_Reports sub-folder beside the canonical gear TOML (or beside the
    explicit --file/-f path). Filenames are lgo_GearReport_###.txt and
    lgo_GearReport_###.html, with a shared serial number per run.
    If the file name or any of the folders in the path have spaces, you'll 
    need to put quote marks around it.

  lgo optimize --builds-file <path> ...
    Override saved-build discovery and use the explicit builds TOML you provide.
    This applies to both `--build <name>` and `--save-build <name>`.
    If the file name or any of the folders in the path have spaces, you'll 
    need to put quote marks around it.

  lgo optimize --save-build <name> <stat:min> [<stat:min> ...]
    Run the optimization normally and also save those goals into the sibling
    file `lgo_<character>_builds.toml` beside the canonical gear TOML.
    If the gear file path itself is custom-named, LGO falls back to the
    top-level `character = "..."` field in that TOML to determine the sibling
    `lgo_<character>_builds.toml` path. If the file does not exist it is
    created. If the build name already exists, matching case-insensitively, it
    is overwritten. Build names are preserved as written for display.

  lgo optimize --build <name>
    Load the named build's saved goals from `lgo_<character>_builds.toml` and
    run optimization with them. No positional goals may be supplied when
    `--build` is used, but it may be combined with `--save-build <newname>` to
    save the loaded goals under a different name. Goal strings in the builds
    file use the same existing `<stat:min>` parser as the CLI: full names and
    two-letter abbreviations are both accepted.

3.5 scrap-gear
  lgo scrap-gear
    Auto-discovers `lgo_<character>_gearReady.toml` and its sibling
    `lgo_<character>_builds.toml`, re-runs the live optimizer once per saved
    build, then lists the items not used in any saved build. The output first
  lists every build evaluated (name plus goals in priority order), then shows
  two simple name-only sections: `Items you can scrap:` for items used by no
  saved build, and `Items of which you have more than one, but only need
  one:` for duplicate-owned items whose extra copies are never needed. It
  prints only to the terminal; no LGO_Reports files are written.

  Count-aware duplicate handling: for each item name, `scrap-gear` compares
  how many copies you own against the maximum number of copies used by any
  one saved build. The report shows item names only, but the underlying
  duplicate-aware accounting is unchanged.

  Empty-slot placeholders, `(2-handed item)` off-hand lines, and `NO ITEMS`
  placeholders are never counted as items.

    If the builds file is missing, empty, or malformed, the command errors
    clearly and tells you to save a build with:
     lgo optimize --save-build <name> <goals...>

  lgo scrap-gear --character <name>
  lgo scrap-gear -c <name>
    Use the specified character's AllServers folder for auto-discovery.

  lgo scrap-gear --file <path>
  lgo scrap-gear -f <path>
    Read the explicit gear TOML you provide and discover the sibling
    `lgo_<character>_builds.toml` beside it. If the filename is custom-named,
    LGO falls back to the top-level `character = "..."` field in that TOML to
    determine the builds filename.
    If the file name or any of the folders in the path have spaces, you'll 
    need to put quote marks around it.

  lgo scrap-gear --builds-file <path>
    Override saved-build discovery and use the explicit builds TOML you
    provide.
    If the file name or any of the folders in the path have spaces, you'll 
    need to put quote marks around it.

3.6 base-stats
  lgo base-stats
    Print the five raw innate Base stats from [InnateStats] in
    lgo_<character>_gearReady.toml, and the 16 derived tracked-stat
    contributions computed from them (already included in optimize totals).
    Does not run an optimization. Requires data/base_stat_derivations.json in
    the current directory's data/ folder, like optimize.
    Auto-discovers lgo_<character>_gearReady.toml the same way optimize does.

  lgo base-stats --character <name>
  lgo base-stats -c <name>
    Use the specified character's AllServers folder for auto-discovery.

  lgo base-stats --file <path>
  lgo base-stats -f <path>
    Read the explicit canonical gear TOML you provide.
    If the file name or any of the folders in the path have spaces, you'll 
    need to put quote marks around it.

3.7 Stat goal syntax
  Goal format: <stat>:<minimum>
  Stat token may be the full canonical stat name or its two-letter abbreviation.

    Armour             am
    Morale             ml
    Power              pw
    CriticalRating     cr
    Finesse            fn
    PhysicalMastery    pm
    TacticalMastery    tm
    OutgoingHealing    oh
    Resistance         rs
    CriticalDefense    cd
    IncomingHealing    ih
    Block              bl
    Parry              pa
    Evade              ev
    PhysicalMitigation pt
    TacticalMitigation tt

  Note: pt and tt are the parser's canonical two-letter abbreviations for
  PhysicalMitigation and TacticalMitigation.

  Examples:
    lgo optimize tm:450000 cr:350000 fn:0
    lgo optimize TacticalMastery:450000 CriticalRating:350000 Finesse:0

3.8 Help
  lgo
  lgo --help
  lgo -h
  lgo help
    Print the usage banner and exit.


SECTION 4 - DEVELOPER COMMANDS (cargo)
--------------------------------------
(used when developing LGO itself)

  All Section 3 verbs and flags work via cargo run -- <verb> [flags]
    See Section 3 for the full catalog.

  cargo clean
    Remove build artifacts (target/).
  cargo build
    Build debug binaries into target/debug/.

  cargo build --release
    Build optimized release binaries into target/release/.
    When cargo build --release runs, every [[bin]] becomes a standalone executable in target/release/

  cargo run -- optimize <stat:min> ...
                   e.g. tm:450000 cr:350000 fn:0
  
  cargo run -- resolve-slots
    Build (if needed) and run lgo; args after -- are passed through to lgo. All Section 3 verbs and flags work this way: cargo run -- <verb> [flags]
    (e.g. cargo run -- base-stats, cargo run -- --statlist). Section 3 is the
    authoritative catalog of verbs and flags; Section 4 only covers build and
    test tooling.

    Tip: cargo build --release produces target/release/lgo, which you can run
    directly (lgo <verb> ...) — but still from a directory containing data/,
    since resolve-slots and optimize resolve data files relative to the
    current directory.

  cargo test
    Run all unit and integration tests.

  cargo test --release benchmark_candidate_scaling -- --ignored --nocapture
    Run the item-pool-size benchmark test

  cargo test -- --ignored
    Run only #[ignore] tests, including the deep optimizer differential fuzzer.

  cargo test <substring>
    Run tests whose names contain <substring>.

  cargo test -- --nocapture
    Run tests and also print test stdout (println!).

  cargo test --test resolve_slots_integration
    Run only tests/resolve_slots_integration.rs.

  cargo fmt
    Format Rust source with rustfmt.

  cargo clippy --all-targets
    Run Clippy lints for the whole crate.

  cargo fmt --check
    Check Rust formatting without rewriting files.


SECTION 5 - ITEMS DATABASE BUILDER
-------------------------------------------------
Build the items database (data/lgo_items.json):
  Dev: cargo run --release -- build-db
  User: lgo build-db
    or: lgo -build-db
    or: lgo --build-db
    or: lgo -b

This reads data/items.xml and produces 'data/lgo_items.json' — each item's canonical slot plus the two_handed flag. Item stats are not part of the database; they come from the bookmarklet.

Working directory matters. db_build resolves data/items.xml and data/lgo_items.json as relative paths. So the user has to run it from a directory that contains a data/ folder with those files (i.e. the LGO repo root, or wherever they keep their copy of the game-data dumps).

So the build-db command will use the items.xml file from the 'data' folder, and the new database file will be written to the 'data' folder too, but both the input and output files can be specified if desired:
  cargo run -- build-db --items <path>/items.xml --out <path>/lgo_items.json

The JSON file is consumed by resolve-slots.
