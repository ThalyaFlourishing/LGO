LGO COMMAND-LINE REFERENCE
==========================

LGO has three command surfaces: an in-game Lua plugin, a browser bookmarklet workflow on lotro-wiki.com, and the lgo Rust CLI. These run in different environments and are documented in separate sections below to avoid confusion.

SECTION 1 - IN-GAME PLUGIN COMMANDS
-----------------------------------
(typed in the LotRO chat window while the plugin is loaded)

  /lgo
    Show plugin help text (lists plugin subcommands and workflow reminder).

  /lgo export
    Export a unified gearlist from equipped items plus Shared Storage chest "lgo".
    Writes lgo_gearlist_*.plugindata.

  /lgo export chest <name>
    Export equipped items plus Shared Storage chest <name>.

SECTION 2 - BOOKMARKLET WORKFLOW
--------------------------------
(no shell command form; browser-driven step that produces the stats .toml)

  1) Open https://lotro-wiki.com in your browser.
  2) Click the LGO Stats bookmarklet.
  3) Paste the contents of lgo_gearlist_<character>_<timestamp>.plugindata when prompted.
  4) Let the bookmarklet fetch item stats and generate TOML output.
  5) Save the generated lgo_stats_*.toml file into your character's AllServers directory.

SECTION 3 - LGO CLI (USER COMMANDS)
-----------------------------------

3.1 General notes
  - Verbs are case-insensitive (for example: optimize, Optimize, OPTIMIZE).
  - Verb aliases:
      optimize       | --optimize       | -o
      resolve-slots  | --resolve-slots  | -r
  - Help/usage banner is printed by:
      lgo
      lgo --help
      lgo -h
      lgo help

3.2 resolve-slots
  lgo resolve-slots
    Auto-detect the latest lgo_stats_*.toml in the selected character's AllServers
    directory, resolve slot names via data/lgo_items.json, and write a sibling
    .toml output.

  lgo resolve-slots --character <name>
  lgo resolve-slots -c <name>
    Resolve slots using that character's AllServers directory.

  lgo resolve-slots --file <path>
  lgo resolve-slots -f <path>
    Resolve slots for the explicit input stats TOML path you provide.
    With --file/-f, that file path is used directly.

3.3 optimize
  lgo optimize <stat:min> [<stat:min> ...]
    Run optimization with stat goals in priority order (first stat maximized,
    later stats used as tie-breakers). A minimum of 0 means maximize with no floor.

  lgo optimize --character <name> <stat:min> ...
  lgo optimize -c <name> <stat:min> ...
    Use the specified character's AllServers folder for auto-discovery.

  lgo optimize --file <path> <stat:min> ...
  lgo optimize -f <path> <stat:min> ...
    Use an explicit lgo_gearlist_*.plugindata input file.
    This --file/-f is for plugindata, not for stats TOML.

    The optimizer's stats TOML is always auto-detected from AllServers
    (latest lgo_stats_*.toml, typically the _resolved file).
    Selecting a specific TOML input for lgo optimize is not currently supported.

  Combined example:
    lgo optimize --character Thalya --file path/to/lgo_gearlist_Thalya_20260601_120000.plugindata tm:450000 cr:350000 fn:0

3.4 Stat goal syntax
  Goal format: <stat>:<minimum>
  Stat token may be the full canonical stat name or its two-letter abbreviation.

    Armor              am
    CriticalRating     cr
    Finesse            fn
    PhysicalMastery    pm
    TacticalMastery    tm
    OutgoingHealing    oh
    Resistance         rs
    CriticalDefense    cd
    IncomingHealing    ih
    Block              bl
    Parry              pa
    Evade              ev
    PhysicalMitigation pt
    TacticalMitigation tt

  Note: pt and tt are the parser's canonical two-letter abbreviations for
  PhysicalMitigation and TacticalMitigation.

  Examples:
    lgo optimize tm:450000 cr:350000 fn:0
    lgo optimize TacticalMastery:450000 CriticalRating:350000 Finesse:0

3.5 Help
  lgo
  lgo --help
  lgo -h
  lgo help
    Print the usage banner and exit.

SECTION 4 - DEVELOPER COMMANDS (cargo)
--------------------------------------
(used when developing LGO itself)

  cargo build
    Build debug binaries into target/debug/.

  cargo build --release
    Build optimized release binaries into target/release/.
    When cargo build --release runs, every [[bin]] becomes a standalone executable in target/release/

  cargo run -- optimize <stat:min> ...
  
  cargo run -- resolve-slots
    Build (if needed) and run lgo; args after -- are passed through to lgo.

  cargo test
    Run all unit and integration tests.

  cargo test -- --ignored
    Run only #[ignore] tests.

  cargo test <substring>
    Run tests whose names contain <substring>.

  cargo test -- --nocapture
    Run tests and also print test stdout (println!).

  cargo test --test resolve_slots_integration
    Run only tests/resolve_slots_integration.rs.

  cargo fmt
    Format Rust source with rustfmt.

  cargo clippy
    Run Clippy lints.

  cargo clean
    Remove build artifacts (target/).

SECTION 5 - ITEMS DATABASE BUILDER
-------------------------------------------------
Build the items database (data/lgo_items.json):
  Dev: cargo run --release -- build-db
  User: lgo build-db

This reads data/items.xml and data/progressions.xml and produces 'data/lgo_items.json'.

The JSON file is consumed by resolve-slots.

Working directory matters. db_build resolves data/items.xml, data/progressions.xml, and data/lgo_items.json as relative paths. So the user has to run it from a directory that contains a data/ folder with those files (i.e. the LGO repo root, or wherever they keep their copy of the game-data dumps). Alternatively they can pass explicit paths:

cargo run --release -- build-db --items   data/items.xml --progressions   data/progressions.xml --out   data/lgo_items.json
                       db_build --items <path>\items.xml --progressions <path>\progressions.xml --out <path>\lgo_items.json
