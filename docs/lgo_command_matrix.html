LGO Command Reference

LGO is run from a command-line window (Command Prompt, PowerShell, or Windows Terminal). Every LGO command has the same shape:

lgo <command> [options] [values]

Things that are true for every LGO command:
  • Capitalisation of command and option names does not matter. optimize, Optimize, OPTIMIZE, --character, and --ChArAcTeR all work the same way.
  • Capitalisation of the values you type is preserved. Character names, file paths, saved-build names, and stat goals are used exactly as you type them.
  • Ask for help any time by adding --help, -h, or help anywhere on the line, or by running lgo with no arguments at all.
  • If you type an option name LGO doesn't recognise, it will stop and tell you: Unknown option: '…'.

Table 1 — The commands at a glance

These are the seven things LGO can do. Each command has a short primary name and, in most cases, one or two shorter forms you can use as a shortcut.

What you want to do Primary command Shortcuts
See the help screen lgo help lgo --help, lgo -h, or just lgo
Look up the two-letter stat abbreviations lgo --statlist lgo statlist
Find the best gear combination for your stat goals lgo optimize lgo --optimize, lgo -o
See which items are unused across all your saved builds lgo scrap-gear lgo scrapgear, lgo --scrap-gear, lgo -s
Show your innate Base stats and what they contribute lgo base-stats lgo --base-stats
Turn a fresh bookmarklet output into your working gear file lgo resolve-slots lgo --resolve-slots, lgo -r
Rebuild the local item database from a new items.xml lgo build-db lgo --build-db, lgo -b

Table 2 — Every option, command by command

Options are the extra switches you can add after a command to change how it behaves. Options that take a value (a name or a file path) expect that value as the very next word on the command line. Flags are on/off switches — just include them or leave them out.

lgo optimize

Runs the optimizer and prints a report. You must give it at least one stat goal or use --build to load a saved one.

Option Short form What it takes What it does
--character -c A character name Chooses which character to optimize for. If you only have one LotRO character with LGO data, this is auto-detected and you don't need this option.
--file -f A path to a .toml file Points LGO at a specific gear file instead of auto-finding your lgo_<character>_gearReady.toml.
--builds-file — A path to a .toml file Points LGO at a specific saved-builds file instead of the one sitting next to your gear file. Only relevant when you also use --build or --save-build.
--build — A saved-build name Runs one of your saved builds by name. Cannot be combined with stat goals on the same line — the saved goals are used instead.
--save-build — A saved-build name After the run finishes, saves the stat goals under this name so you can re-run them later. If the name already exists, it is overwritten. Requires at least one stat goal (or --build).
--to-file — (flag) In addition to printing the report to the screen, writes a text copy and a self-contained HTML copy into an LGO_Reports folder beside your gear file.
(stat goals) — One or more <stat>:<minimum> entries Your priority-ordered list of what you want. See Writing stat goals below.

lgo scrap-gear

Reruns every saved build against your current gear file, lists the saved builds first, then shows two simple name-only sections: items you can scrap entirely, and items of which you have more than one but only need one.

Option Short form What it takes What it does
--character -c A character name Chooses which character to check. Auto-detected if you have only one.
--file -f A path to a .toml file Points LGO at a specific gear file instead of auto-finding it.
--builds-file — A path to a .toml file Points LGO at a specific saved-builds file instead of the one sitting next to your gear file.

lgo base-stats

Prints your five raw Base stats (Might, Agility, Vitality, Will, Fate) and shows how they translate into the tracked stats the optimizer uses. Does not run an optimization.

Option Short form What it takes What it does
--character -c A character name Chooses which character to read. Auto-detected if you have only one.
--file -f A path to a .toml file Points LGO at a specific gear file instead of auto-finding it.

lgo resolve-slots

Reads the fresh *_gearStats.toml produced by the bookmarklet and folds it into your working *_gearReady.toml file. Run this every time you have a new bookmarklet output to import.

Option Short form What it takes What it does
--character -c A character name Chooses which character to update. Auto-detected if you have only one.
--force -f (flag) Turns on interactive mode: for each item that would be changed or removed, LGO stops and asks you y (yes), n (no), or a (yes to all remaining of the same kind). Without this flag, your existing hand-edited entries are preserved untouched.

lgo build-db

Rebuilds the local item database. You only need this when a new LotRO update adds items that LGO doesn't recognise yet. See the workflow document for how to obtain a fresh items.xml.

Option Short form What it takes What it does
--items — A path to an .xml file The items file to read from. Defaults to data\items.xml.
--out — A path to a .json file Where to write the rebuilt database. Defaults to data\lgo_items.json.

lgo --statlist

Has no options. Prints a two-column table of the 16 stat abbreviations and their full names.

Writing stat goals

Stat goals only apply to lgo optimize. Each goal is written as:

<stat>:<minimum>

where <stat> is either the full stat name (for example TacticalMastery) or its two-letter abbreviation (tm), and <minimum> is the number you want that stat to reach.

  • List your goals in priority order. LGO satisfies higher-priority goals first, then reaches for lower-priority ones.
  • A minimum of 0 means "no floor, but maximise this stat once the important goals are met."
  • Run lgo --statlist to see the full list of stat abbreviations.

Example:

lgo optimize tm:450000 cr:350000 fn:0
